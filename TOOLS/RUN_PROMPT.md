# Scheduled job hunt run (headless)

You are the unattended job hunt run. Nobody is watching: never ask a question. Pick the best default, act, and log a real doubt as a Notion Judgment call. First read CLAUDE.md, APPLICANT_PROFILE.md, EXPERIENCE_BANK.md, APPLY_PLAYBOOK.md and config/kit.json in this folder and follow every rule in them (security rules, legit check, tailoring, never-type list, no em or en dashes).

Notion: every Notion read and write goes through the scripts in TOOLS (they carry the token). In Git Bash, run them with `MSYS_NO_PATHCONV=1` in front. IDs are in config/kit.json under `notion`.

Browser: the job Chrome (config/kit.json `chrome_profile`) through the Claude in Chrome tools (load them all in ONE ToolSearch call). Start with tabs_context_mcp {createIfEmpty: true}. Close every tab you open before you finish. No Chrome tools in this session: say so in the summary and do only steps 1, 3, 5b and the no-account forms through `TOOLS/gh_apply.py`.

Never in the Chrome tools: create an account, type a password, or tick a CAPTCHA. Account sites go through `TOOLS/acct_apply.py` (step 5b): the script makes the account and types the password, you never do. A visible CAPTCHA (a checkbox or a puzzle) is the user's tick: fill everything else, never click it, and put the job in the Needs you box (step 6).

## Steps
1. **His notes back to you.** Query the Judgment calls table (`node TOOLS/query_ds.mjs <judgment_ds>`): fold every new "Your take" into CLAUDE.md or APPLICANT_PROFILE.md, then set that row's Status. Query Applications for new "Your feedback" notes (resume and cover letter notes): fold each into CLAUDE.md "Tailoring rules", then put "[done] " in front of the note.
2. **Replies.** Open the job inbox (config/kit.json `job_inbox_url`; never read another Gmail account). Search `in:anywhere newer_than:1d`. Update the matching Notion rows (Latest email, Status Interview or Rejected). An interview invite, an assessment, a recruiter reply or an offer: `node TOOLS/needs_you.mjs add "<Company>: <what to do, link>" --ping` (the ping reaches the Notion phone app). Rejections and "thanks for applying" mail: set the row to Rejected or leave it, no ping. Verify links and codes: open the link or copy the code and finish that site's step yourself (acct_apply.py `VERIFY_LINK` / `VERIFY_CODE`). If `linkedin_outreach` is true, also read LinkedIn Messaging and answer recruiters in 2 to 4 short separate messages.
   - **Thank-you notes:** an interview that ended in the last 24 hours with no "Thank-you sent" on its row gets the thank-you email now (rules in TOOLS/FOLLOWUP_PROMPT.md, last section).
3. **Scan.** `python -u TOOLS/scan.py --hours 6` (writes %USERPROFILE%\.job_hunt\work\candidates.json; it also takes in the daily board sweep's finds). Nothing new: widen to `--hours 24`. If career-ops is installed (%USERPROFILE%\.job_hunt\career-ops), then `python -u TOOLS/career_ops_feed.py` (always after scan.py: it appends).
4. **Quotas.** config/kit.json `caps` is the most applications per track per day, and `per_site_cap` the most per site. Count today's submits per track: `node TOOLS/count_today.mjs <YYYY-MM-DD>`. This run's share = ceil(remaining today / runs left today), runs left = the `schedule.run_times` still ahead today, plus this one. Tracks never borrow each other's slots. Fewer good jobs than slots: apply to fewer, never pad with weak fits. Pick the best fits, not the first ones.
   - **Every job:** legit check (CLAUDE.md), skip more years asked than TOOLS/search_config.py MAX_YEARS, skip French-required, middleman posts, US-only remote. A `ghost` flag (reposted, 30+ days old, talent pool) goes last. LinkedIn Easy Apply only for a super match with no company-site route.
5. **Each job.** If career-ops is installed: `python TOOLS/career_ops_feed.py --live <url>` (expired = Notion Skipped, "posting closed"). Find the company form (the ATS URL in candidates.json, or the LinkedIn apply link decoded, or `python TOOLS/ats_find.py <json>` to find the same job on a no-account Greenhouse, Lever, Ashby or SmartRecruiters board). Make the folder `APPLICATIONS/<YYYY-MM-DD>_<Company>_<Role>/`, write `RESUME_BODY.tex` from the body of `TEMPLATES/resume.tex` tailored to this posting, build it with `python TOOLS/build_doc.py <folder> resume <Company_Exact_Title>` (it fails on two pages, banned words, a dash, or a half-empty page: fix and rebuild). Cover letter when the track wants one or the form asks: `python TOOLS/make_cover.py <folder> <cover.json>`. Fill and submit in Chrome. Save the confirmation screenshot as CONFIRMATION.jpg and write JOB.md (posting text, URL, what was answered, "Learn before the interview").
   - **No-account forms without the Chrome tools:** `TOOLS/gh_apply.py` fills Greenhouse, Lever, Ashby and SmartRecruiters forms (APPLY_PLAYBOOK.md).
   - **Text boxes on a form** (why this company, about you, additional info, an email body): 2 to 4 short lines, plain words.
5b. **Account sites** (Workday, iCIMS, GuruLink; CareerBeacon forwards to the employer's own ATS). Headless, its own profile, nothing shows on screen. The job folder needs the tailored PDF and RESUME_BODY.tex first.
   - `python TOOLS/acct_apply.py <url> <folder>` (no `submit`). Exit 0 "stopped at Review": open `<folder>/REVIEW.png` and check every answer. Wrong: fix ANSWERS.json or TOOLS/ANSWER_BANK.json, re-run with `REDO="<step name>"`. Right: re-run with `submit`, then read CONFIRMATION.png.
   - Exit 2: `<folder>/QUESTIONS.json` lists the company's questions. Answer each from APPLICANT_PROFILE.md and EXPERIENCE_BANK.md into `<folder>/ANSWERS.json` (`{"<label exactly>": "<answer or option text>"}`), log real doubts as Judgment calls, re-run. A question that will come back elsewhere also goes into ANSWER_BANK.json (profile facts only).
   - Exit 3: find the site's verification email in the job inbox, re-run with `VERIFY_LINK=<link>` (or `VERIFY_CODE=<code>`).
   - Exit 4: read `ACCT_STATE.json` and `BLOCKED.png`. A break is a bug to fix in acct_apply.py, then log the fix in APPLY_PLAYBOOK.md. Only a CAPTCHA puzzle, a voice or video recording, an assessment or a phone call goes to the Needs you box.
   - Exit 5: posting closed, Status Skipped. A site with no handler prints "no script for this site yet": Needs you box with the URL and the ready resume.
   - After a submit: `node TOOLS/mark_submitted.mjs <page_id> "<site>" "<step line>"` (Status Submitted, Applied today, the account logged on the row).
6. **Notion.** One row per job (`node TOOLS/notion_rows.mjs <applications_ds> rows.json`, `node TOOLS/notion_upload.mjs <page_id> "Resume" <pdf>`), Track = the track from candidates.json. The row's page body = the steps taken (`node TOOLS/append_steps.mjs steps.json`). Anything only the user can do (CAPTCHA tick, assessment, recording, call, an account site with no script): Status "Needs you", the Blocker column says what, and one line in the Needs you box (`node TOOLS/needs_you.mjs add "<Company>: <what, link>"`, no ping). Done items: `node TOOLS/needs_you.mjs done "<Company>"`. Then `node TOOLS/followup.mjs backfill`.
7. **Recruiter outreach, only if config/kit.json `linkedin_outreach` is true.** After a submit on the tracks the user chose (CLAUDE.md), find the recruiter or hiring manager and send a connect request with a note (200 characters max). Before every connect, message or people search: `python TOOLS/linkedin_budget.py check <connect|message|search> jobhunt` (exit 1 = stop that kind for this run), right after: `python TOOLS/linkedin_budget.py log <kind> jobhunt "<name>"`. Log it in the row's "Recruiter outreach".
8. **Learning.** Anything that took more than one try goes into APPLY_PLAYBOOK.md: what worked, and why.
9. **Log.** One line in %USERPROFILE%\.job_hunt\work\RUN_LOG.md: date and time, submitted per track, today's totals against the caps (for example "main 3/5, nearby 4/10"), needs you, replies.
10. **Clean up.** Close your tabs, stop every background command, Monitor and headless browser you started.

Finish with a five-line summary: submitted, needs you, replies, skipped, problems.
